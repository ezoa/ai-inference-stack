# AI Inference Stack

A self-hosted AI coding service: **Qwen3-Coder-30B-A3B** (4-bit AWQ) served
locally with **vLLM** on an NVIDIA GPU, behind a **LiteLLM** gateway, with
optional **private HTTPS access from your own devices via Tailscale**.

Everything runs in Docker on one machine. After the one-time model download,
no data leaves the machine.

- OpenAI-compatible API at `http://127.0.0.1:4000/v1`, model name **`qwen-coder`**
- Model runs entirely on the local GPU — no cloud API costs, works offline
- Optional private remote access over HTTPS, restricted to your Tailscale network
- Web dashboard (a feature of the LiteLLM image, not configured in this repo)
  at `/ui/` for usage and API-key management

For architecture details, see **[docs/system-design.md](docs/system-design.md)**.

## Prerequisites

| Requirement | Why | How to check |
|---|---|---|
| Docker Engine + Docker Compose | Runs all services | `docker compose version` |
| NVIDIA GPU + driver (`nvidia-smi` works) | Model inference | `nvidia-smi` |
| NVIDIA Container Toolkit | Lets Docker use the GPU | `make check-gpu` |
| `openssl` | Generates the API key during setup | `openssl version` |
| ~17 GB free disk (observed; exact size is set upstream) | One-time model download | `df -h` |
| Tailscale *(only for remote access)* | Private HTTPS access | `tailscale version` |

> **GPU memory:** the repository does not state a minimum. On the reference
> machine (24 GiB RTX 4090) the stack uses ~23 GiB with
> `--gpu-memory-utilization 0.90` and a 32K context — a 24 GiB-class GPU is
> the practical floor for this configuration.

## Configuration

All secrets live in **`.env`** (git-ignored, permissions `600`). It must
contain:

| Variable | Purpose | Example / format |
|---|---|---|
| `LITELLM_MASTER_KEY` | API key for every gateway request and UI login | `sk-<random hex>` (generated by `make setup`) |
| `POSTGRES_PASSWORD` | Password for the PostgreSQL container | any strong password |
| `DATABASE_URL` | Tells LiteLLM where the database is | `postgresql://litellm:<POSTGRES_PASSWORD>@db:5432/litellm` |

Notes:

- The host part of `DATABASE_URL` must stay `db` — that is the Docker service
  name, resolvable only inside the stack's network.
- **Known gap:** `make setup` currently generates **only** `LITELLM_MASTER_KEY`.
  The two database variables must be added to `.env` manually before the first
  `make up` (the `db` service cannot start without `POSTGRES_PASSWORD`).
- Never commit `.env` or paste its values into public places.

## Daily commands

All commands run from the repository root.

### Start / stop

```bash
make setup        # one-time: checks tools, creates .env with a master key
make check-gpu    # verify Docker can see the GPU
make up           # start vLLM + LiteLLM + PostgreSQL (downloads model on first run)
make stop         # stop containers (keep them)
make start        # start existing containers again
make down         # stop and remove containers
make status       # show container status
make logs         # follow all logs (also: logs-vllm, logs-litellm)
make update       # pull newest images and restart
make clean        # remove containers, keep volumes
make reset        # WARNING: also deletes volumes (model cache!) — asks to type RESET
```

### Verify it works

```bash
make health       # gateway alive?        -> "I'm alive!"
make models       # model registered?     -> list contains "qwen-coder"
make test         # end-to-end: model list + a real test message
```

> **After a reboot or first start:** containers auto-start
> (`restart: unless-stopped`), but the model takes a few minutes to load into
> the GPU. API errors during that window are normal — wait and re-run
> `make test`.

## Private access (from your phone / laptop)

The gateway is bound to `127.0.0.1` only. Remote devices reach it through
Tailscale, which exposes it as HTTPS **only to devices in your tailnet**:

```bash
make remote-up      # checks prerequisites, then: sudo tailscale serve --bg 4000
make remote-status  # show the active URL
make remote-down    # disable remote access (sudo tailscale serve off)
```

Then from any device on your tailnet, use:

```
https://<machine-name>.<tailnet>.ts.net/v1/...
```

(Tailscale issues a valid HTTPS certificate automatically. The exact hostname
is shown by `make remote-status` — it is machine-specific and not stored in
this repo.)

**Security notes**

- Every request still requires the master key — remote access is *network*
  restriction, not a replacement for the API key.
- Strangers on the internet cannot reach the gateway: port 4000 is published
  on localhost only, and Tailscale access requires tailnet membership.
- The LiteLLM web UI at `/ui/` (and remotely at `https://<...>/ui/`) logs in
  with username `admin` and the master key as the password.

## Example API requests

Replace `<LITELLM_MASTER_KEY>` with the value of `LITELLM_MASTER_KEY` from
`.env`.

### List models

```bash
curl http://127.0.0.1:4000/v1/models \
  -H "Authorization: Bearer <LITELLM_MASTER_KEY>"
```

### Chat completion (curl)

```bash
curl http://127.0.0.1:4000/v1/chat/completions \
  -H "Authorization: Bearer <LITELLM_MASTER_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-coder",
    "messages": [{"role": "user", "content": "Write a Python function that checks if a string is a palindrome."}],
    "max_tokens": 1024
  }'
```

Add `"stream": true` to receive tokens as they are generated.

### Python (openai library)

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:4000/v1",
    api_key=os.environ["LITELLM_MASTER_KEY"],  # export it first
)
response = client.chat.completions.create(
    model="qwen-coder",
    messages=[{"role": "user", "content": "Explain list comprehensions in Python."}],
    max_tokens=1024,
)
print(response.choices[0].message.content)
```

### From a remote device

Same requests, but the base URL is
`https://<machine-name>.<tailnet>.ts.net/v1` (from `make remote-status`).

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `500 ... Cannot connect to host vllm:8000` right after start | Model still loading (normal for a few minutes) | Wait, then `make test`; watch `make logs-vllm` |
| Gateway unreachable / connection refused | Containers not running | `make status`, then `make up` |
| `401 Unauthorized` | Wrong or missing master key | Check the `Authorization: Bearer` header against `.env` |
| Dashboard shows `Not connected to DB!` | `db` unhealthy or DB vars missing from `.env` | `make status`; confirm `POSTGRES_PASSWORD` and `DATABASE_URL` exist in `.env`, then `make up` |
| Docker error `could not select device driver "nvidia"` | NVIDIA Container Toolkit missing | Install it, then `make check-gpu` |
| vLLM exits with CUDA out of memory | GPU too small or already busy | Lower `--max-model-len` or `--gpu-memory-utilization` in `docker-compose.yml`, then `make up` |
| `make remote-up` says Tailscale is not authenticated | Not logged in | `sudo tailscale up`, then retry |
| Remote URL does not load | `tailscale serve` not enabled, or device not in the tailnet | `make remote-status`; confirm the device runs Tailscale and is logged into the same tailnet |
